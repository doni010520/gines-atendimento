# Redesign do painel admin — GINES Atendimento

**Data:** 2026-09-07
**Status:** aprovado pelo usuário (direção visual e estrutura)

## Problema

O painel está feio, e a maior parte disso não é questão de gosto — são três defeitos mecânicos:

1. **A fonte nunca carrega.** `src/app/layout.tsx` importa Geist e Geist Mono e registra em
   `--font-geist-sans` / `--font-geist-mono`; `src/app/globals.css` então declara
   `body { font-family: Arial, Helvetica, sans-serif; }`, que atropela o `--font-sans` do
   `@theme inline`. O painel inteiro renderiza em Arial.
2. **Todas as bordas são pretas.** O projeto usa Tailwind 4.3.3. No v4 o `preflight.css` define
   `border: 0 solid` sem cor, então a classe `border` resolve para `currentColor` — aqui,
   `#171717`. Todo card, input, select, linha de tabela e divisória do app está com borda
   quase preta. Confirmado no `node_modules/tailwindcss/preflight.css:15`.
3. **Metadados do template.** `title: "Create Next App"`, `description: "Generated by create
   next app"`, `<html lang="en">` num app 100% em português.

Somados a isso: raios inconsistentes (`rounded` 4px nos inputs vs `rounded-xl` 12px nos cards),
zero elevação, emoji como ícone (💬 🏡 🗑), nenhum estado de foco visível, e duas tabelas
`STATUS_LABEL` divergentes (uma em `inbox/page.tsx`, outra em `imoveis/StatusSelect.tsx`).

Além da aparência, duas telas têm problema de estrutura:

- **Cadastro de imóvel:** 18 campos empilhados sem agrupamento, mais 2 textareas e 3 uploads;
  o botão de salvar fica no fim de uma página muito longa.
- **Tela de conversa:** altura do chat travada em `65vh`/`75vh` (buraco no desktop, aperto no
  celular) e o botão **"Assumir atendimento"** — a ação mais importante do painel — mora numa
  coluna lateral que, no celular, cai abaixo do chat inteiro.

## Decisões tomadas

| Pergunta | Resposta |
|---|---|
| Identidade visual | Não existe — criar do zero |
| Quem usa, onde | Misto: corretor no celular (Inbox), admin no desktop (Imóveis). Nenhum dos dois é segunda classe |
| Escopo | Camada visual **+** conserto estrutural onde dói. Nada de regra de negócio |
| Direção visual | **A · Confiança sóbria** — azul-marinho institucional, cinza-azulado frio, dourado discreto pro que urge |

### Fora de escopo (deliberado)

- Dark mode. O `globals.css` já documenta a decisão de ficar só no claro; mantida.
- Nova dependência de UI (shadcn, Radix, biblioteca de ícones). Ícones serão SVG inline.
- Rework de navegação/arquitetura de informação. Continuam as duas abas, Inbox e Imóveis.
- Qualquer alteração em agente, webhooks, motor de follow-up, tools ou schema do banco.
- **Filtro "minhas conversas".** A tabela `conversations` tem `assigned_user_id`, então daria pra
  separar o que o corretor logado assumiu do que está com os colegas. Fica de fora de propósito:
  é funcionalidade nova, não redesenho, e o usuário optou por não mexer em arquitetura de
  informação. Registrado aqui porque o dado existe e a pergunta vai voltar.

## Sistema de design

### Tokens de cor

Definidos como CSS custom properties em `globals.css` e expostos ao Tailwind via `@theme inline`,
para que virem utilitários (`bg-surface`, `text-ink-muted`, `border-border`).

**Neutros**

| Token | Valor | Uso |
|---|---|---|
| `--color-canvas` | `#F7F8FA` | Fundo da aplicação |
| `--color-surface` | `#FFFFFF` | Cards, header, linhas de tabela |
| `--color-surface-muted` | `#FBFCFD` | Fundo de input, área de chat |
| `--color-border` | `#E3E7ED` | Borda padrão |
| `--color-border-strong` | `#CFD6E0` | Divisória com mais peso |
| `--color-ink` | `#16202E` | Texto principal |
| `--color-ink-muted` | `#64748B` | Texto secundário |
| `--color-ink-subtle` | `#94A3B8` | Terciário (horários, placeholders) |

**Marca**

| Token | Valor | Uso |
|---|---|---|
| `--color-primary` | `#1B3A5C` | Botão primário, marca no header |
| `--color-primary-hover` | `#16304C` | Hover do primário |
| `--color-primary-soft` | `#E8EEF6` | Fundo de badge azul |
| `--color-primary-ink` | `#2C4E77` | Texto sobre `primary-soft` |

**Estados** — um par `soft`/`ink` por estado, para badge e faixa:

| Estado | soft | ink | Onde aparece |
|---|---|---|---|
| Atenção (aguardando corretor) | `#FBF2E0` | `#8A5F14` | Badge "Aguardando", faixa de handoff |
| Sucesso (em atendimento) | `#E4EFE8` | `#2A5C3F` | Badge "Em atendimento", botão Assumir |
| Neutro (encerrado) | `#EEF1F5` | `#64748B` | Badge "Encerrado" |
| Perigo | `#FEF3F2` | `#B42318` | Zerar conversa, erro de login |

### Tipografia

Geist já está instalada e carregada — o conserto é remover o `font-family: Arial` do `body` e
deixar o `--font-sans` do `@theme` valer. Nenhuma fonte nova entra no projeto.

| Papel | Tamanho / peso |
|---|---|
| Título de página | 20px / 600, `tracking-tight` |
| Nome em lista (celular) | 15px / 600 |
| Corpo | 14px / 1.5 |
| Secundário | 12px |
| Rótulo de seção | 10px / 800, caixa alta, `tracking-[.09em]`, cor `primary` |
| Micro (horário, dica) | 11px |

### Forma e profundidade

- Raios: `--radius-sm: 6px` (input, botão pequeno), `--radius-md: 8px` (botão), `--radius-lg: 12px`
  (card), `999px` (pill de status).
- Sombras: `--shadow-sm: 0 1px 2px rgba(22,32,46,.05)` em cards; `--shadow-md: 0 4px 12px
  rgba(22,32,46,.08)` em elementos flutuantes; barra fixa usa sombra invertida
  `0 -2px 10px rgba(22,32,46,.05)`.
- Foco: `outline: 2px solid var(--color-primary); outline-offset: 2px` em todo elemento
  interativo. Hoje não existe nenhum estado de foco visível.
- Transições: `transition-colors` de 150ms em botões e links. Nada de animação além disso.

## Componentes novos

Extraídos para evitar a repetição de classnames que já causou a divergência das duas
`STATUS_LABEL`. Cada um com uma responsabilidade só, sem estado interno além do que já existe.

| Arquivo | O que é | Depende de |
|---|---|---|
| `src/lib/ui/status.ts` | Fonte única de verdade: mapa de status → rótulo + tom, para conversa (`bot`/`queued`/`open`/`closed`) e imóvel (`ativo`/`reservado`/`vendido`/`inativo`) | nada |
| `src/components/icons.tsx` | SVG inline: inbox, prédio, lixeira, enviar, voltar, check. Substitui os emoji | nada |
| `src/components/ui/button.tsx` | `Button` com variantes `primary` / `secondary` / `ghost` / `danger` / `success` e tamanhos `sm` / `md`. Server component; o estado `pending` continua no `FormSubmitButton` existente | tokens |
| `src/components/ui/badge.tsx` | Pill de status; recebe o tom de `lib/ui/status` | `status.ts` |
| `src/components/ui/card.tsx` | `Card` e `CardHeader` — superfície + borda + raio + sombra | tokens |
| `src/components/ui/field.tsx` | `Field` (label + input), `SelectField`, `TextareaField`, `FileField`. Move os helpers privados de `PropertyForm` pra cá | tokens |
| `src/components/ui/form-section.tsx` | `FormSection` — rótulo, dica e conteúdo agrupado, com divisória | tokens |

`FormSubmitButton` continua existindo e passa a aceitar `variant`, delegando o estilo ao `Button`.

## Mudanças por tela

### `src/app/globals.css`

Substituir o bloco atual pelos tokens acima, mantendo o comentário que explica a decisão de não
ter dark mode. Definir explicitamente `border-color` padrão como `var(--color-border)` num
`@layer base` — isso conserta as bordas pretas de todo o app de uma vez, sem tocar em nenhuma
classe `border` espalhada pelos componentes. Remover `font-family: Arial`.

### `src/app/layout.tsx`

`lang="pt-BR"`. `title: "GINES · Atendimento"`, `description` descrevendo o painel de verdade.

### `src/app/(admin)/layout.tsx`

Header com a marca em `primary`, navegação com estado ativo visível (hoje Inbox e Imóveis são
indistinguíveis quando você está numa delas), nome e papel do usuário melhor apresentados,
"Sair" como `ghost`. Mesma server action `signOut`.

### `src/app/(admin)/MobileTabBar.tsx`

Emoji → SVG. Estado ativo com cor `primary` e não só peso da fonte. Mantém `min-h-14` e o
`env(safe-area-inset-bottom)`.

### `src/app/(admin)/inbox/page.tsx`

**Agrupamento aprovado:** a lista deixa de ser cronológica achatada e passa a ter três seções,
cada uma com contador:

| Seção | Status | Por quê |
|---|---|---|
| **Precisam de você** | `queued` | O robô pediu humano e ninguém assumiu. É o motivo de abrir o painel |
| **Em andamento** | `bot`, `open` | Conversas vivas. O badge diz quem está dirigindo — robô ou corretor |
| **Encerradas** | `closed` | Fora do caminho, mas acessível |

O corretor abre o painel pra saber onde é necessário; hoje isso fica afogado no meio das conversas
que o robô já está resolvendo.

Agrupamento é client-side sobre os mesmos dados: a query continua `order by last_message_at desc
limit 100`, sem mudança. Dentro de cada grupo a ordem cronológica se mantém. Card com borda
esquerda âmbar de 3px no grupo urgente. `STATUS_LABEL` local sai, entra `lib/ui/status`.

### `src/app/(admin)/inbox/[id]/page.tsx`

- Altura: `65vh`/`75vh` fixos saem. O chat passa a ocupar a altura real disponível
  (`h-[calc(100dvh-…)]` no celular, coluna flexível no desktop), com `dvh` para não brigar com a
  barra do navegador móvel.
- Cabeçalho da conversa com nome, imóvel e preço em uma linha, mais o badge de status.
- **Faixa de handoff:** quando `status === "queued"`, uma faixa âmbar acima do chat com o tempo
  de espera e o botão **Assumir**. Some nos outros status. O tempo sai de `last_message_at`, que
  já existe — sem coluna nova.
- Balões: entrada em `surface-muted` com canto vivo à esquerda, saída em `primary` com canto vivo
  à direita, internas em âmbar centralizadas (como hoje, só que com os tokens).
- A coluna lateral guarda o que não é urgente: dados do contato, imóvel, "Devolver pro robô" e
  "Zerar conversa".

### `src/app/(admin)/imoveis/PropertyForm.tsx`

Seis `FormSection`, na ordem em que se pensa um imóvel:

1. **Identificação** — título, tipo, sinônimos, modalidade, status
2. **Valores** — preço, condomínio, IPTU
3. **Onde fica** — cidade, bairro, endereço
4. **O imóvel** — quartos, suítes, vagas, área construída, área do terreno, características
5. **O que o robô fala** — copy completa, variações do título do anúncio
6. **Materiais** — vídeo, PDF, fotos

Barra de salvar fixa no rodapé (`sticky bottom-0`) com sombra invertida. Os helpers `Field`,
`Select` e `FileField` saem daqui e viram os componentes compartilhados.

**Nada muda no contrato:** mesmos `name` de campo, mesma `saveProperty`, mesmo `FormData`.
Rejeitadas: sanfona (esconde campo que se precisa achar rápido) e wizard de etapas (hostil pra
editar, que é o uso mais comum depois do cadastro).

### `src/app/(admin)/imoveis/page.tsx`

Tabela e cards com os tokens. Preço com mais peso visual. "Materiais" vira grupo de chips
(vídeo / PDF / N fotos) em vez de texto concatenado por `·`. `+ Novo` como `Button` primário.

### `src/app/(admin)/imoveis/StatusSelect.tsx`

Estilo do select alinhado ao sistema; rótulos vindos de `lib/ui/status`.

### `src/app/(admin)/inbox/SendMessageForm.tsx` e `ResetButton.tsx`

Só estilo e ícone. A proteção contra toque duplo do `SendMessageForm` e o `confirm()` do
`ResetButton` ficam exatamente como estão.

### `src/app/login/page.tsx`

Card com a marca GINES acima do formulário, campos com foco visível, erro no tom de perigo,
botão primário de largura total.

## Verificação

O projeto não tem framework de teste (sem `test` no `package.json`, sem arquivo de teste). Montar
um só pra isso está fora de escopo, então a verificação é a que o projeto comporta hoje:

1. `npx tsc --noEmit` limpo (passa hoje — tem que continuar passando).
2. `npm run lint` limpo.
3. `npm run build` completa.
4. Passagem visual com o dev server em todas as seis telas — login, inbox lista, conversa nos
   quatro status, imóveis lista, imóveis novo, imóveis editar — em viewport de celular (375px) e
   de desktop, com screenshot de cada.
5. Conferência de que nenhum `name=` de campo do `PropertyForm` mudou, comparando com
   `saveProperty` em `imoveis/actions.ts`.

## Risco

O risco real é regressão funcional silenciosa num formulário que só é exercitado à mão. A
mitigação é o item 5 acima: os `name` dos campos são o contrato entre o form e a server action, e
é o único lugar onde um erro de digitação passa pelo TypeScript sem reclamar.
